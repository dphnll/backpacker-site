# Clavelo Landing (formerly Backpacker)

Публичная точка входа Clavelo. Статические HTML, CSS и один локальный
JavaScript-файл для языка и типографики; без сборки и зависимостей.

Задача страницы:

1. за несколько секунд объяснить, что Clavelo помогает спланировать свою
   поездку или подготовить её для других;
2. дать каждой из трёх ролей узнать свой сценарий: путешественнику,
   организатору, участнику;
3. привести человека в работающее приложение, а организатора ещё и к
   письму о пилоте;
4. держать стабильный публичный HTTPS-адрес политики конфиденциальности для
   Chrome Web Store.

## Границы

Этот репозиторий не касается ничего из перечисленного:

- `01_app` — canonical приложение;
- `02_demo` — деплой приложения на GitHub Pages;
- `03_extension` — Chrome Extension;
- `05_native` — Capacitor-оболочка.

Landing остаётся отдельным репозиторием и не меняет PWA, Extension или их
production-конфигурацию. Публикационный target — отдельный Git-backed
Cloudflare Pages project для `backpacker-site` с целевым custom domain
`clavelo.cc`. Старый лендинг `backpackerapp.cc` получает 301 по точному хосту
только после проверки нового сайта, с сохранением пути и query.
Существующий `backpacker-app` / `app.backpackerapp.cc` к этому deployment
не относится и остаётся доступным без редиректа.

Текстовая часть перехода на Clavelo и утверждённый финальный logo asset pack
интегрированы в release candidate. Бренд-видимые кадры приложения и
`assets/og-image.jpg` переснимаются только из локального candidate App, без
временных логотипов. Ветка ребрендинга не предназначена для публикации до
отдельного release gate.

```
                               та же копия лежит в 01_app
```

## Устройство страницы (v2)

Clavelo — одна система с тремя сценариями, а не три продукта. Страница
сначала даёт каждому узнать себя, потом показывает его сценарий:

| # | Раздел | Что в нём |
| --- | --- | --- |
| 01 | Герой | одно обещание для всех ролей; живой момент поездки и тот же момент в Clavelo. На 375×812 видны заголовок, обе кнопки в ряд и начало фото |
| 02 | Кто вы в этой поездке? | три навигационные карточки: Путешествую · Организую · Участвую |
| 03 | Для организаторов | одна композиция в один экран 1280×800 на всех семи языках: заголовок, три действия (собрать, поделиться, обновлять — смета остаётся у вас), кому это, кнопки; справа фото группы и целый экран телефона организатора |
| 04 | Для гостей и участников | что человек получает по ссылке; три дня визита в Тбилиси |
| 05 | Для своих поездок | Собрать → Разложить → Пользоваться в поездке |
| 06 | С чего начнём? | приложение или письмо о пилоте |

CTA ведут только туда, что существует: корень приложения с `?lang=`,
опубликованное расширение Chrome и `mailto:hello@clavelo.cc` с темой
письма на языке страницы. Прямого маршрута в Organizer Mode у приложения
нет, поэтому лендинг его не придумывает, а объясняет, где режим включается:
«Поделиться поездкой» → «Вести поездку для группы», вход по email.

## Визуальный язык

Палитра и шрифт — из приложения (`01_app/styles.css`, токены `--a-*`):

```
--paper    #f6f1e7     --kraft  #ede0c6
--card     #fffdf9     --deep   #1d3b35   тёмная полоса организатора
--ink      #1c1a17     --slate  #44637e   корешки карточек событий
--ink-soft #6f675c     --ochre  #8a6d2e   приложения — цвета ролей
--brand    #2f5d55     --terra  #a2503a
```

Шрифт — Inter 400/600, те же два `woff2`, что в приложении, локально, без
CDN. Для грузинского и армянского — системный fallback (`Noto Sans
Georgian`, `Noto Sans Armenian`, `Segoe UI`), для китайского — системные
CJK-шрифты.

**Карта — среда, как на главной приложения.** Та же старинная карта мира
лежит под всей страницей в `body::before` с `position: fixed`; маска и
прозрачность взяты из приложения (`opacity: .4`, градиент 26% / 74%).
Источник — `05_design/2010x1400_capuchin_2017.jpg`: на телефоне
`map-portrait.webp`, тот же фрагмент Атлантики, что в приложении, но из
исходника в полтора раза крупнее; с 700 px — `map-wide.webp`, карта целиком,
чтобы не растягивать узкий кадр втрое. Контрастные полосы (организаторы,
свои поездки) лежат поверх карты и закрывают её.

**Полоса падающих плиток** по правому краю перенесена из v0: мотив экрана
приветствия приложения, восемь типов событий, цикл 13 секунд. Не ловит
касания, гаснет при `prefers-reduced-motion`. Количество, размер, скорость
и прозрачность (`opacity: .3`) те же, что в v0, на всех ширинах.

**Слои:** карта (`z-index: -1`) → фоны контрастных полос → плитки (`0`) →
содержимое разделов в `.wrap` (`1`). Плитки идут и поверх тёмной и
крафтовой полос, но всегда под текстом, фото и снимками.

**Правило контраста над картой** (из v0, замерено по файлу карты): под слоем
0,4 фон в худшем месте опускается до 165 из 255; `--ink-soft` даёт на нём
2,25, `--ink` — 7,02. Поэтому текст, лежащий прямо на карте, всегда `--ink`,
иерархию держит кегль. На крафте и голубой подложке второстепенный текст —
`--ink-muted` `#554d43` (6,3:1); на тёмной полосе — бумага (11,5:1 и 8,1:1).

**Три роли — настоящие экраны приложения.** Путешествую и Организую — по
две карточки событий веером (корешок типа, иконка, время), снятые на
синтетическом визите: жильё и прогулка; встреча в аэропорту и ужин со
сметой организатора. Участвую — не карточки, а гостевой экран: блок
«О программе», каким его видит участник. Так третья роль не повторяет
вторую.

**Движение.** Фото героя проявляется, телефон поднимается; карточки ролей
расходятся веером и кадры приподнимаются при наведении. При
`prefers-reduced-motion: reduce` анимаций и переходов нет совсем.

### Типографика

Правила зашиты в `i18n.js` и работают на всех языках при выводе, а не в
переводах:

- значимая фраза — с новой строки: элемент с `data-phrases` режется на
  предложения (включая армянскую «։» и китайскую «。»), каждое — свой блок;
- короткие слова (предлоги, союзы, артикли, любое слово до двух букв)
  привязаны к следующему неразрывным пробелом; тире и стрелка не начинают
  строку; число не отрывается от слова;
- отдельные фразы — без точки в конце (проверяется тестом);
- тире — «–», не «—» (проверяется тестом).

### Ролевые кадры: синтетический визит

Экраны организатора и участника требуют серверной публикации и входа по
email, а публиковать ради картинки вымышленную программу в production нельзя.
Поэтому `capture-roles.mjs` работает только с **локальной** сборкой
приложения и с закрытой сетью:

1. кладёт в localStorage синтетический «Визит в Тбилиси» на 12–14 ноября
   2026: ни одной реальной организации, гостя или брони; участники —
   нейтральные инициалы;
2. вызывает те функции приложения, которыми оно само рисует эти экраны:
   `openTrip` для организатора, `readOnlyShare` + `showTripScreen` для
   участника;
3. участнику отдаёт ровно ту проекцию, которую приложение публикует, —
   `buildPublishedTripState()`, то есть без сметы организатора;
4. обрывает все запросы на внешние хосты, кроме статической библиотеки
   supabase-js с CDN: ни сессии в Supabase, ни аналитики.

```bash
git -C ../01_app archive origin/main | tar -x -C /путь/к/папке
python -m http.server 4190 --bind 127.0.0.1    # из этой папки
node capture-roles.mjs                          # LOCALES=ru,en — выборочно
```

### Кадры путешественника

`capture.mjs` снимает тренажёр «Казань соло» и пишет PNG; `to-webp.mjs`
перекодирует их в WebP рядом с исходником:

```bash
node capture.mjs
node to-webp.mjs crop-ai crop-day crop-budget
```

Правила любой пересъёмки: только синтетические данные или тренажёр, без
имени профиля, почты, кодов броней и вложений; один viewport для всех кадров;
файл легче 200 КБ.

## Аналитика

На Landing v0 аналитики нет: ни одного стороннего скрипта, ни одного запроса на
внешний хост. Когда решение о трекинге будет принято отдельно, разумный
минимальный набор событий выглядит так:

- `landing_opened` — открытие страницы;
- `cta_open_app_clicked` — нажатие «Открыть Clavelo» (герой и закрытие
  различаются параметром);
- `cta_extension_clicked` — нажатие CTA расширения, когда оно появится;
- `cta_store_clicked` — нажатие store-бейджа, когда он появится.

Это описание, а не задача к реализации.

## Локализация

Одна разметка обслуживает семь языков: `ru`, `en`, `fr`, `ka`, `de`, `hy`, `zh`.
Приоритет: сохранённый ручной выбор, whitelist-параметр `?lang=`, первый
поддерживаемый язык браузера, затем English. Ошибка `localStorage` не блокирует
страницу. Выбранная локаль попадает в URL, во все ссылки на приложение и в
тему письма о пилоте.

Немецкий лендинг обращается на «Sie», как приложение Clavelo; тест
запрещает формы «du». Подсказка про режим организатора цитирует подписи
кнопок приложения дословно на каждом языке.

Privacy Policy сохраняет только утверждённые English / Русский тексты;
переводы legal-документов в этот слайс не входят.

## Точки расширения

CTA Chrome Web Store опубликован по действующему URL. В закрывающем блоке
остаётся только закомментированный будущий слот Google Play / App Store /

## Автономная копия для показа

Чтобы показать лендинг человеку без сервера и без папки с ассетами:

```bash
node bundle.mjs
node verify.mjs preview/Clavelo-лендинг.html
```

`bundle.mjs` вшивает стили, оба шрифта и все снимки в сам HTML и кладёт
результат в `preview/` — два самодостаточных файла, лендинг и политика
конфиденциальности, со ссылками друг на друга. Открываются двойным кликом.
Снимки вшиваются на одном языке, `BUNDLE_LOCALE` (по умолчанию `ru`).
`verify.mjs` проверяет, что внутри не осталось ни одной ссылки на диск.

Папка `preview/` не коммитится: она пересобирается одной командой.

## Локальный просмотр

Файлы статические. Для полной проверки URL-параметра и `404.html` используйте
локальный HTTP-сервер из корня репозитория; например:

```bash
python -m http.server 4173 --bind 127.0.0.1
```

Preview: `http://127.0.0.1:4173/?lang=en`.

## Выпуск и кэш

На `clavelo.cc` Cloudflare отдаёт HTML с `max-age=0`, а CSS, JS и картинки —
с `max-age=14400`: это Browser Cache TTL зоны, 4 часа. На `*.pages.dev` у всех
файлов `max-age=0`, поэтому превью ветки этого не показывает.

Первый выпуск v2 сломался именно на этом. Адреса `styles.css` и `i18n.js` в
v1 и v2 одинаковые, и вернувшийся посетитель получал свежий HTML v2 со
старыми CSS и JS v1 из своего кэша: старые тексты, растянутые фото. F5 не
помогает — Chrome перепроверяет только документ. Откат ломался зеркально
у тех, кто успел открыть v2.

Правило: **у каждого изменяемого файла адрес меняется вместе с содержимым.**

- `node version-assets.mjs` считает версию — первые 10 знаков sha256 от
  `styles.css`, `i18n.js` и всех снимков интерфейса — и вписывает `?v=…` в
  `index.html`, privacy, terms, 404 и `ASSET_VERSION` в `i18n.js` (по ней же
  `i18n.js` строит адреса снимков при смене языка).
- Тест падает, если версия устарела: изменили CSS, JS или снимок и не
  запустили скрипт — выпуска не будет.
- Фото, карта, шрифты и логотип не версионируются: их адреса неизменяемы,
  новое содержимое кладётся под новым именем файла.

После публикации:

```bash
node check-production.mjs
```

Скрипт читает HTML как браузер и сверяет, что CSS, JS, снимки, privacy и
terms на `clavelo.cc` одной версии, а HTML не кэшируется.

## Выпуск на новом домене

1. Завершить согласованный релиз Clavelo #42 и опубликовать лендинг из PR #2.
2. Подключить `clavelo.cc` к существующему Pages project лендинга, проверить HTTPS, `/`, `/privacy/`, `/terms/`, семь языков, соцпревью и кнопки приложения.
3. Затем включить 301 только для хоста `backpackerapp.cc`, сохранив путь и query. Проверить старый `/privacy/` и прямой доступ к `app.backpackerapp.cc`.
4. При сбое выключить правило 301; приложение и его домен не переключать.

Адрес расширения в Chrome Web Store меняется отдельным выпуском; старый `/privacy/` продолжает открывать тот же документ через редирект.
