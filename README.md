# Backpacker Landing v0

Публичная точка входа Backpacker. Статические HTML и CSS, без сборки, без
зависимостей, без JavaScript.

Задача страницы — три вещи и ни одной больше:

1. за несколько секунд объяснить, что такое Backpacker;
2. привести человека в работающее приложение;
3. держать стабильный публичный HTTPS-адрес политики конфиденциальности для
   Chrome Web Store.

## Границы

Этот репозиторий не касается ничего из перечисленного:

- `01_app` — canonical приложение;
- `02_demo` — деплой приложения на GitHub Pages;
- `03_extension` — Chrome Extension;
- `05_native` — Capacitor-оболочка.

Причина не стилистическая, а техническая. В манифесте расширения объявлено
`externally_connectable: https://dphnll.github.io/*`, а приложение живёт по пути
`/Backpacker_demo/`. Смена пути или origin приложения ломает handshake
расширения, scope service worker и уже установленные PWA. Landing поэтому —
отдельный project repo, а приложение остаётся ровно там, где было.

**Про будущий собственный домен.** Домен, привязанный к *пользовательскому*
сайту `dphnll.github.io`, переносит на себя все project pages аккаунта, включая
приложение, — и ломает то, что описано выше. Домен, привязанный к этому
project-репозиторию, затрагивает только его. Подключать домен нужно здесь.

## Визуальный язык

Источник истины — композиционный слой главной в `01_app/styles.css` (токены
`--a-*`). Значения перенесены один в один:

```
--paper    #f6f1e7
--card     #fffdf9
--ink      #1c1a17
--ink-soft #6f675c
--line     rgba(28,26,23,.1)
--brand    #2f5d55
```

Шрифт — Inter 400/600, те же два `woff2`, что в приложении, локально, без CDN.
Kicker капсом с `letter-spacing: .1em`, радиус карточки 18, радиус кнопки 14,
основная кнопка `min-height: 54px`.

**Устройство страницы повторяет главную приложения.** Карта из `01_app` лежит в
`body::before` с `position: fixed` и не едет со скроллом; маска и прозрачность
взяты из приложения один в один (`opacity: .4`, градиент 26% / 74%). Содержимое
живёт в непрозрачных бумажных плашках `.card` поверх неё — по той же причине,
по которой они существуют в приложении: текст не должен лежать на карте.

`position: fixed`, а не `background-attachment: fixed` — второй игнорируется на
iOS, и карта поехала бы вместе с содержимым.

По правому краю идёт полоса падающих плиток — мотив с экрана приветствия
приложения (`.intro-floater`, `@keyframes intro-float`): те же восемь типов
событий, та же приглушённая палитра корешков, тот же цикл 13 секунд с
отрицательными задержками, за счёт которых лента с первого кадра выглядит
идущей, а не начинающейся. Полоса зафиксирована, лежит слоем с картой ниже
содержимого, не ловит касания и полностью гаснет при `prefers-reduced-motion`.

### Вертикальный ритм

Между всеми плашками — **один и тот же шаг `--block: 100px`**, на всех ширинах.
Он задаётся в одном месте: `main` раздаёт его между блоками, сетка
доказательств берёт то же значение. Ни одна секция не носит собственных
вертикальных полей — иначе расстояния расходятся (было 160 / 80 / 68). Новый
раздел встаёт в общий ритм сам, без правки отступов.

Поля от краёв экрана `--pad`: 36 / 56 / 80 px по брейкпоинтам — вдвое шире
внутреннего ритма приложения, чтобы карта дышала вокруг плашек, а не
выглядывала полоской.

### Правило контраста над картой

Замерено по самому файлу карты: средняя светлота 194, минимальная 50, 3,3%
пикселей темнее 120. Под слоем `opacity: .4` это даёт фон от 222 в среднем до
165 в худшем месте. На таком фоне:

| Цвет | средний фон | худший фон |
| --- | --- | --- |
| `--ink-soft` `#6f675c` | 4,16 | 2,25 |
| `--ink` `#1c1a17` | — | 7,02 |

Отсюда правило, зашитое в CSS: **`--ink-soft` живёт только на плашках, а текст,
лежащий прямо на карте, всегда `--ink`.** Иерархию в таких местах держит кегль,
не цвет. Сейчас прямо на карте лежат пять элементов главной (кикер, H1, лид,
подпись под кнопкой, H2 закрытия) и ссылка «← Backpacker» в документах — все в
`--ink`.

Чего на странице нет и не должно появиться: Literata, IBM Plex, рваной бумаги,
штампов, скотча, иллюстрации рюкзака из концепт-макетов, legacy-палитры teal и
Roboto. Всё это либо не реализовано в продукте, либо перекрыто в нём.

## Скриншоты

Целый экран телефона показывается **один раз** — в герое. Он сообщает «продукт
мобильный», и повторять это четыре раза подряд не нужно. В блоках-доказательствах
стоят фрагменты интерфейса: знаковый кусок, относящийся именно к этой функции.

Все кадры — **настоящие**, сняты с работающего приложения на данных тренажёра
«Казань соло». Заглушек не осталось.

| Файл | Что в кадре | Размер |
| --- | --- | --- |
| `shot-home.jpg` | Целый главный экран: тренажёр, «Создать поездку», «Идеи» | 750×1624 |
| `crop-day.png` | Два дня подряд с четырьмя типами карточек | 800×1360 |
| `crop-card.png` | Карточка изнутри: форма со всеми полями | 800×1523 |
| `crop-budget.png` | Бюджет 45 000 ₽ · Оплачено · Бронь · Свободно | 800×535 |
| `crop-ai.png` | Поле описания поездки и кнопка «Надиктовать» | 800×437 |
| `og-image.jpg` | Карточка для ссылок в мессенджерах | 1200×630 |

Фрагменты кадрируются вплотную к своему объекту, без окружающей подложки:
рамку даёт сам интерфейс, а на странице у `.crop` нет ни границы, ни фона —
иначе получается коробка внутри коробки.

Каждый фрагмент обёрнут в ссылку на приложение. Причина: на снимках видны
кнопки, и человек по ним нажимает. Ссылкой сделан весь кадр, а не отдельная
область — обещать интерактив одной кнопке на картинке было бы обманом.
Отдельных адресов для конкретных экранов у приложения нет, поэтому все четыре
ведут в корень.

Формат выбран по содержимому: герой содержит фотографию обложки — это JPEG;
фрагменты интерфейса плоские — это PNG.

### Как переснять

`capture.mjs` в корне репозитория снимает все кадры автоматически: поднимает
headless Chrome, ходит по приложению и пишет PNG. Зависимостей нет — CDP через
встроенный в Node WebSocket, поэтому `npm install` не нужен.

```bash
node capture.mjs
```

Кадры уходят в `assets/` рядом со скриптом; исходный размер потом уменьшается
до значений из таблицы выше. Переменные окружения `APP_URL` и `OUT_DIR`
позволяют снять с другой сборки или в другую папку.

Скрипт сам выставляет viewport 375×812 в 2×, проставляет
`backpacker.onboarding.v1 = seen`, чтобы не поймать в кадр приветствие, гасит
сплэш, открывает тренажёр и кадрирует по CSS-селекторам, а не по пикселям.
Он же учитывает липкую шапку поездки: кадр не начинается выше её низа, иначе
она попадает в снимок размытой полосой.

Правила, которые нужно соблюдать при любой пересъёмке:

- только данные тренажёра «Казань соло», без реальных поездок;
- без имени профиля, почты, кодов броней и вложений;
- один и тот же viewport для всех кадров, чтобы масштаб интерфейса совпадал;
- держать вес файла ниже ~200 КБ.

Размеры зафиксированы в атрибутах `width` / `height` самих `<img>`, поэтому
место под кадр резервируется до загрузки. Если новый кадр выйдет другой
пропорции, поправить нужно два числа в атрибуте — и `alt`, который описывает
конкретное содержимое снимка.

## Аналитика

На Landing v0 аналитики нет: ни одного стороннего скрипта, ни одного запроса на
внешний хост. Когда решение о трекинге будет принято отдельно, разумный
минимальный набор событий выглядит так:

- `landing_opened` — открытие страницы;
- `cta_open_app_clicked` — нажатие «Открыть Backpacker» (герой и закрытие
  различаются параметром);
- `cta_extension_clicked` — нажатие CTA расширения, когда оно появится;
- `cta_store_clicked` — нажатие store-бейджа, когда он появится.

Это описание, а не задача к реализации.

## Точки расширения

В разметке уже заготовлены и закомментированы два слота:

- CTA Chrome Web Store в блоке расширения — включается заменой строки-статуса
  на ссылку, класс `.btn-secondary` уже описан;
- ряд бейджей Google Play / App Store / TestFlight в закрывающем блоке — класс
  `.store-row` уже описан.

Ни один из них не включается, пока нет реального публичного URL.

## Локальный просмотр

Файлы статические, специальный сервер не нужен — `index.html` открывается прямо
в браузере. Единственное отличие от продакшена: `404.html` использует абсолютные
пути от `/backpacker-site/`, поэтому локально по `file://` его стили не
подхватятся. Все остальные страницы связаны относительными ссылками и локально
выглядят как на сервере.

## Перед первым деплоем

1. Подставить `[EFFECTIVE_DATE]` в `privacy/index.html` (два места: EN и RU).
2. Подставить `[CONTACT_EMAIL]` в `privacy/index.html` (два места: EN и RU).
3. Решить, появляется ли контакт в подвале `index.html` — слот закомментирован.
4. Создать репозиторий `backpacker-site`, включить Pages из ветки `main`, папка
   `/`.
5. Внести адрес `/privacy/` в поле политики конфиденциальности листинга Chrome
   Web Store и в `[POLICY_URL]` исходного `03_extension/docs/PRIVACY_POLICY.md`.
